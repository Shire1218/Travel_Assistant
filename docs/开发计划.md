# 旅行计划管理系统 · 开发计划

> 版本：v1.0（2026-10-10），配合《需求规格说明书》使用。
> 按里程碑顺序推进，每个里程碑有明确验收标准；不含时间承诺，按实际节奏推进。

---

## 1. 工程结构（Monorepo）

```
travel_system/
├── docs/                    # 需求与设计文档
├── frontend/                # Vben Admin v5（Vue3 + TS + Vite）
│   └── src/views/           # 计划列表、计划编辑器、系统管理页面
├── backend/                 # NestJS + TS
│   └── src/
│       ├── modules/         # auth / plan / place / day / activity /
│       │                    # transport / optimize / budget / luggage / pdf / admin
│       └── common/          # 高德 API 客户端、异常、守卫
├── docker-compose.yml       # nginx + backend + mysql（仅部署用）
└── README.md                # 本地开发与部署说明
```

开发环境：两台 Windows 开发机均可 `npm run dev` 直跑（Node 20 LTS + 本地 MySQL 8），不依赖 docker；docker-compose 仅用于服务器部署。

## 2. 里程碑

### M0 工程脚手架
- 初始化 frontend（Vben Admin v5 精简）与 backend（NestJS）工程
- MySQL 建库、TypeORM 连接、迁移机制跑通
- 统一响应结构与异常处理；前端对接登录接口打通
- **验收**：登录/登出全流程可用；一条示例 CRUD 走通前后端与数据库

### M1 用户与计划管理
- 注册/登录/个人信息（Vben 体系）
- 管理员：用户管理、系统设置（高德两个 key 的存取）
- 计划 CRUD + 复制 + 列表页
- **验收**：两个账号各自建计划，互相不可见；复制计划内容完整

### M2 景点库与地图（核心）
- 高德 JS API 集成：地图组件、POI 搜索、逆地理编码、标记拖动
- 三种选点交互（搜索加入 / 点击创建 / 拖动微调）；去重提示
- 共享地点库 CRUD；加入计划生成快照；"同步最新"
- **验收**：在地图上以三种方式为计划添加 10+ 地点，字段完整入库；B 用户可见并复用 A 录入的地点

### M3 行程编排
- 天管理（日期绑定、插入/删除顺延、日备注、当晚住宿）
- 候选池与"分配到天"；活动 CRUD、拖拽排序
- 时间轴自动推算接口（首活动时刻 + 时长 + 交通耗时串联；锁定/手改重算）
- 冲突检测四规则（重叠/闭馆/衔接/过晚）标红提示
- 内嵌联动小地图（按天着色 + 连线 + 序号）
- **验收**：完成一个 3 天 8 景点的行程编排，时间轴正确推算，人为制造冲突均被检出

### M4 交通
- 高德路径规划封装：一对坐标 → 多方式备选方案（距离/耗时/参考费用）
- 距离阈值推荐规则；选定方案落库进入行程与预算
- 跨城段（手填班次时刻）参与时间轴
- **验收**：任意相邻两点可选定备选交通方案；跨城高铁段正确影响当日时间轴

### M5 路线优化
- 精确算法实现（分支定界/Held-Karp，≤12 点 + 闭馆约束）
- 优化预览（新旧地图+时间轴对比）与应用
- **验收**：构造已知最优解的用例，算法结果一致；预览确认后计划数据正确更新

### M6 预算
- 五类明细归集（活动/交通/住宿自动 + 购物/其他独立项）
- 三层汇总（单项→日→总账）+ 总预算上限超支红字
- **验收**：明细变动实时反映到三层汇总；超预算时编辑页出现红字提示

### M7 行李管理
- 行李清单 CRUD + 分类 + 已装包勾选；新建计划带出内置模板
- **验收**：新计划自动生成模板条目，可增删改勾选

### M8 PDF 导出
- HTML 模板设计（封面/总览/每日表/静态地图/预算/清单/注意事项；A4 竖版、页眉页脚页码、简约清新）
- 高德静态地图出图（点位+序号+连线）；Puppeteer 生成与下载
- **验收**：对一个完整计划导出 PDF，各板块齐全、版式无溢出无错位、地图清晰

### M9 部署
- docker-compose（Nginx + backend + MySQL）、环境变量与 key 配置
- 上线清单（数据库初始化、管理员账号、key 配置）与 README
- **验收**：服务器 docker-compose up 一键起服务，注册登录到导出 PDF 全流程可用

## 3. 依赖关系与推进顺序

```
M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9
        │________│（M3 依赖 M2 地图与地点）
                 │___________│（M3 时间轴依赖 M4 交通耗时，M3/M4 可穿插联调）
```

- M2、M3、M4 为核心主链，优先保证质量
- M5 依赖 M4 的耗时数据；M6 依赖 M3/M4 的明细来源
- M8 依赖 M2~M7 全部数据就绪，放最后收口

## 5. 风险与应对

| 风险 | 应对 |
|---|---|
| 高德免费额度或接口变更 | 所有高德调用收敛到后端统一客户端，便于切换/缓存；关键结果（距离/耗时/费用）落库，不重复调用 |
| Vben Admin 定制计划编辑器样式冲突 | 编辑器页面独立于 Vben 主题体系，仅复用其框架层（登录/菜单/请求） |
| Puppeteer 在服务器环境的 chromium 依赖 | 部署镜像使用官方 node + chromium 依赖层，M9 提前验证 |
| 时间轴推算与手动修改的边界情况 | M3 联调期以"锁定/重算"规则为测试重点，编写边界用例 |
