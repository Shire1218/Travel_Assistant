# 旅行计划系统 · 需求澄清问题清单（第 1 轮）

> 使用方式：问题按模块分组编号，可在对话中按编号回答（如 "A1: Web，A2: 只有自己用……"），也可以直接在本文件每个问题下方补写回答。
> 标注 ⭐ 的是影响整体架构的关键问题，建议优先明确。

## ✅ 已确定的关键决策

| # | 问题 | 结论 |
|---|------|------|
| A1 | 系统形态 | **Web 网页应用**（前后端） |
| D17 | 距离计算 | **接入地图 API**（高德/百度，真实交通距离与耗时） |
| D19 | 排程方式 | **半自动**：用户指定每天去哪些景点，系统优化每日内顺序 |
| D18 | 优化目标 | **第一版先就近贪心排序**，后续再迭代真正的优化算法 |

## A. 产品定位与使用者

1. ⭐ 系统形态是什么：Web 网页 / 桌面应用 / 手机 App（或小程序）/ 命令行工具？
2. 给谁用：只有自己用，还是家人朋友一起用，或打算做成面向公众的产品？
3. 是否需要用户注册登录？还是打开即用、数据只保存在本地？
4. 是否需要同时管理多个旅行计划？要不要状态分类（草稿 / 进行中 / 已完成）？
5. 使用节奏：出行前一次性做好计划，还是旅途中也会频繁修改、随时查看？

## B. 目的地（城市 / 景点 / 酒店）

6. ⭐ 目的地数据从哪来：手动录入名称地址 / 内置景点库 / 接入地图 API 搜索（如高德 POI）？
7. ⭐ 景点和酒店是否记录经纬度坐标？（这是计算距离、地图展示、路线优化的前提）
8. 酒店是全程一家，还是支持中途换酒店（多个住宿据点）？
9. 是否支持多城市行程？跨城交通（高铁 / 飞机）算不算系统管理的对象？
10. 景点需要哪些信息：开放时间、门票价格、建议游玩时长、评分、是否需预约、备注……
11. 范围：只做国内，还是也要支持境外（涉及地图数据源、币种、时差）？

## C. 活动

12. 活动有哪些属性：名称、所在地点、日期、时间段 / 时长、费用、备注……
13. 活动与地点的关系：一个地点可以挂多个活动吗？活动能否独立于景点存在（如"看一场演出"）？
14. 时间排到什么粒度：精确到时刻（14:00–16:00），还是上午 / 下午 / 晚上时段，或只到"第几天"？
15. 需要冲突检测吗（两个活动时间重叠、或路程上来不及时提醒）？
16. 活动要不要分类标签（观光 / 餐饮 / 购物 / 娱乐 / 休息）？会影响预算分类和 PDF 展示。

## D. 距离、交通与路线优化

17. ⭐ 距离怎么算：直线距离 / 调地图 API 拿真实的步行·驾车·公交距离和耗时 / 手动填写？（接 API 需注册 key，免费额度有限）
18. ⭐ "最优路线"优化什么：总交通时间最短 / 总花费最低 / 每天安排尽量充实 / 多目标加权？
19. ⭐ 优化范围：只对"某一天内的景点顺序"排序，还是系统自动决定"哪些景点放哪一天"（含每天从酒店出发、返回酒店）？
20. 支持哪些交通方式：步行 / 驾车 / 打车 / 公交 / 地铁 / 骑行 / 跨城火车 / 飞机？同一段路程要不要提供多种备选方案？
21. 交通方式由用户指定，还是系统按距离 / 预算自动推荐？
22. 要不要地图可视化：网页里内嵌地图看路线，PDF 里也放路线示意图 / 截图？

## E. 预算

23. 预算汇总到哪几层：按单个活动 / 交通、按天、按类别（吃住行游购娱）、按总账？
24. 要不要"计划预算 vs 实际花费"对比（旅途中记录实际支出）？还是第一版只做计划预算？
25. 要不要设置总预算上限，并在超支时提醒？
26. 币种：仅人民币，还是需要多币种（配合境外游）？

## F. 行程结构

27. 计划的数据结构是否为：计划 → 天（Day1…DayN）→ 每天若干"交通 + 活动"？还是不按天组织、只有地点清单？
28. 计划本身需要哪些元信息：标题、目的地、出行日期范围、同行人数、备注、封面图……
29. 要不要"模板"或"复制历史计划"功能（如经典的"北京三日游"一键复制）？

## G. PDF 导出

30. PDF 希望包含哪些板块：封面、行程总览、每日安排表、路线示意、预算明细、注意事项 / 打包清单页……
31. 风格偏好：简约商务 / 活泼多彩 / 多套模板可切换？有没有觉得"格式美观"的参考样例（如携程、马蜂窝的行程单）？
32. 版式：A4 竖版？需要页眉页脚、页码吗？
33. PDF 里要不要嵌入地图图片？
34. 除 PDF 外还需要其他导出格式吗（长图 / Markdown / Excel）？

## H. 技术与部署

35. ⭐ 技术栈有无偏好或限制：前端（Vue / React / 纯 HTML）、后端（Python / Node / Java / 无后端）、存储（SQLite / MySQL / 浏览器本地存储）？
36. 部署方式：自己电脑上跑就行，还是要部署到服务器供多人访问？
37. 界面语言：仅中文，还是需要中英文切换？

## I. 范围与优先级

38. ⭐ 第一版（MVP）的核心闭环是什么：例如"录入景点活动 → 自动排每日路线 → 汇总预算 → 导出 PDF"，其中哪些必须第一版就有，哪些可以往后放？
39. 明确本期不做的功能：如多人协作、分享链接、景点收藏、攻略社区、订票跳转……
40. "最优路线"的智能程度：简单规则排序（就近贪心）够用，还是期望真正的优化算法（如遗传算法 / 精确求解）？
41. 数据量级预期：一个计划大约几个城市、玩几天、包含多少个景点活动？（影响算法与界面设计）
42. 有没有必须在第一版就做的"亮点功能"（如地图可视化、预算图表、行程时间轴）？
